# Комплекты в инвентаризации «Управление IT-отделом»

Как конфигурация хранит комплект (например, «Комплект: Компьютер») и как с этим работать в инвентаризации.
Выяснено по исходникам формы документа «Инвентаризация» и по данным боевой базы.

## Модель данных

- Сам комплект — карточка номенклатуры (`КарточкиНоменклатуры`), стоит на месте хранения (обычно «Рабочее место» под
  каким-то местом верхнего уровня).
- Комплектующие — тоже карточки либо позиции «Не ведётся учёт по карточкам»; в регистре накопления `Остатки`
  у комплектующей **измерение `Партия` = карточка комплекта**. Так десктопная форма находит состав:
  `Остатки(&Период, Партия = &КарточкаКомплекта)`.
- Колонка `Комплект` в таблице `Документы.Инвентаризация.ТаблицаИнвентаризацииПоОстаткам(…)` у комплектующих
  в боевой базе пустая; она заполняется только для вложенных комплектов (регистр `Комплектация`).
  Поэтому связь «комплектующая → комплект» берётся из `Партия`, если там карточка и она не равна собственной.
- Комплект с комплектующими нельзя разобрать «на месте»: техник разбирает его в 1С и собирает заново.
  Поэтому при инвентаризации **скан комплекта отмечает его целиком** (вместе с вложенными комплектами).

## Реализация на планшете

- `ИнвЗагрузить` отдаёт в каждой строке `kit`/`kitName`; ключ строки включает партию, так что одинаковая номенклатура
  в комплекте и «россыпью» не склеивается.
- `ИнвСкан` для карточки возвращает `under` — признак, что предмет стоит на подчинённом месте выбранного места.
  Если список загружен без подчинённых, страница предлагает перезагрузить его «с подчинёнными», сохранив уже отмеченное.
- Страница выстраивает строки деревом (комплект → комплектующие, со сдвигом) и при скане комплекта отмечает всех потомков.
